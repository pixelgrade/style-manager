# Style Manager Modernization Plan (Merged)

Date: 2026-03-03  
Target Baseline: Node 22 + npm 10, PHP 8.1+

## 1. Goals

- Modernize the development stack to current standards.
- Keep release zips stable, reproducible, and activation-safe.
- Reduce build fragility by removing deprecated tooling and unnecessary downgrade complexity.

## 2. Non-Negotiable Guardrails

- Do not delete lockfiles as a default workflow (`package-lock.json`, `composer.lock` must be kept for reproducibility).
- Every phase must produce a buildable plugin zip.
- Fail fast on missing required tools (`wp`, `zip`, `composer`, `node`).
- Validate autoloader integrity in every release build.

## 3. Current State Snapshot

- Node is pinned to 14 via `.nvmrc` / engines lock script.
- Build chain is webpack + gulp with legacy pieces (`gulp-exec`, `gulp-clean`, `gulp-rsync`, `request`, `worker-loader`).
- PHP baseline is now 8.1+ in plugin metadata/composer.
- Build is currently destructive and sequence-sensitive.

## 4. Execution Plan

### Phase A: Node 22 Foundation (low risk, immediate)

1. Set Node baseline:
- `.nvmrc` -> `22`
- `.node-version` -> `22`
- `package.json` engines -> Node 22 / npm 10

2. Validate:
- `npm install`
- `npm run compile:production`
- `npm run zip`

3. Exit criteria:
- Build passes on Node 22 without manual intervention.

### Phase B: Critical Build Stabilization (high value)

1. Remove hard blockers:
- Replace `gulp-exec` zip invocation with `child_process.spawn` (or `execa`) with inherited stdio.
- Replace deprecated `request` in `tasks/google-fonts.js` with native `fetch`.

2. Remove stale gulp dependencies:
- Replace `gulp-clean` with `del`/`fs.rm`.
- Replace `gulp-rsync` with direct `rsync` shell wrapper or native copy + pruning.
- Remove `gulp-sass-unicode` if charset cleanup is already handled in stream.

3. Exit criteria:
- `npm run zip` succeeds consistently and no `maxBuffer` failures remain.

### Phase C: JS Toolchain Refresh (medium risk)

1. Upgrade core packages in controlled batches:
- `webpack` -> latest v5
- `webpack-cli` -> latest v6
- `babel-loader` -> latest v10
- `@babel/core`, `@babel/preset-env`, `@babel/preset-react` -> latest v7
- `sass` -> latest v1
- `sass-loader` -> latest v16
- `mini-css-extract-plugin` -> latest v2
- `terser`/`terser-webpack-plugin` -> latest compatible

2. Webpack 5 cleanups:
- Remove `worker-loader`; switch to native `new Worker(new URL(..., import.meta.url))`.
- Reassess SVG pipeline (`svg-sprite-loader` / `svg-inline-loader`), migrate if maintenance risk is confirmed.

3. Optional React track:
- If moving React 17 -> 18, migrate to `createRoot` and re-test customizer mounts.

4. Exit criteria:
- No frontend regressions in Customizer.
- Bundle output diffs reviewed and accepted.

### Phase D: PHP/Composer Modernization on 8.1+ (medium risk)

1. Remove obsolete downgrade flow:
- Keep `pre-build` without Rector downgrade step.
- Remove dead downgrade script definitions and stale references.

2. Upgrade PHP tooling stack:
- `phpunit/phpunit` -> current supported major for PHP 8.1+
- `wp-coding-standards/wpcs` -> v3.x
- `dealerdirect/phpcodesniffer-composer-installer` -> v1.x
- Re-evaluate `psr/container` upgrade to v2 when code compatibility is confirmed.

3. Reassess polyfills:
- Remove `symfony/polyfill-php72` for PHP 8.1 baseline.
- Keep/remove `symfony/polyfill-mbstring` based on real runtime assumptions and package requirements.

4. Exit criteria:
- Unit/integration tests pass on PHP 8.1 and 8.2.
- Release build has no autoload references to stripped or dev-only packages.

### Phase E: Reproducible Release Pipeline (high value)

1. Build determinism:
- Stop deleting `composer.lock` during packaging.
- Use locked installs for repeatable outputs.

2. Integrity checks:
- Add script to fail if `vendor/composer/autoload_files.php` references removed/dev paths.
- Add script to assert `vendor/composer/installed.json` contains expected production entries only.

3. Artifact verification:
- Capture baseline zip and manifest before each major phase.
- Compare new zips against baseline for unexpected file-level changes.

4. Exit criteria:
- Two clean builds on same commit produce equivalent manifests/checksums.

### Phase F: CI/CD Modernization (high value)

1. Replace Travis with GitHub Actions.
2. Add matrix:
- Node 22
- PHP 8.1, 8.2
3. Jobs:
- JS build
- PHP lint/static checks/tests
- Zip build + artifact upload
- Optional activation smoke test in WordPress test site

4. Exit criteria:
- CI is required for merges to `main`.
- Release candidate zip is generated by CI and matches local release checks.

## 5. Recommended PR Sequence

1. PR1: Node baseline + `gulp-exec`/`request` replacement.
2. PR2: JS dependency core upgrades + worker migration.
3. PR3: PHP tooling upgrades + remove obsolete downgrade machinery.
4. PR4: Reproducible build hardening + autoload integrity scripts.
5. PR5: GitHub Actions rollout.
6. PR6 (optional): Gulp/Webpack unification (webpack-only or Vite evaluation).

## 6. Verification Checklist (run per phase)

- `npm install`
- `npm run compile:production`
- `npm run zip`
- `composer validate`
- Plugin activation test on local WP
- Zip manifest diff vs baseline

## 7. Definition of Done

- Node 22 is enforced and stable for local/CI builds.
- PHP 8.1+ is fully reflected in code, tooling, and tests.
- No deprecated critical build dependencies remain.
- Release zip is deterministic, activation-safe, and CI-produced.
